Open 5250 Guide

Open 5250 is a 5250 screen server that runs on IBM i. The PC needs only a browser: you start a session from the admin screen and open the 5250 screen in a browser tab. From RPG and CL, you can drive sessions with the ILE API (library I5250).

1 Installation, starting and ending

  • The installation directory is /i5250. For the installation steps, see README_ja.md in the distribution.
  • The ILE API and CL commands are restored into library I5250 from the save file I5250.SAVF in the distribution (IBM i V7R4M0 or later; for the steps, see section 2.2 of the Open 5250 manual).

Starting and ending the admin screen (for administrators)

CommandBehavior
I5250/STRI5250Starts the admin screen (batch job I5250ADM; the default job queue is QSYS/QSYSNOMAX = subsystem QSYSWRK). With RESTART(*YES), it ends all 5250 sessions and the admin screen, then starts only the admin screen.
I5250/ENDI5250Ends all 5250 sessions and the admin screen. OPTION(*CNTRLD) (the default) waits up to DELAY seconds (default *NOLIMIT = no limit) for each session to return to the sign-on screen or be disconnected; when that time is exceeded, it signs off with SysReq → 90 and disconnects, the same as *IMMED. The values and defaults are the same as for ENDSBS.
  • Only users with user class *SECOFR can run these commands. The parameters are described in the F1 help.
  • The interactive jobs of the 5250 sessions run in QINTER, separately from the admin screen. Ending only the admin screen job I5250ADM with ENDJOB does not stop the 5250 sessions.
  • Progress is logged to log/i5250cmd.log in the installation directory. From a shell, you can also start and stop the admin screen with start-admin.sh / stop-admin.sh.

2 Using it from a browser

Starting a session

MethodOperation
Admin screenOpen http://<IBM i>:5250/ in a browser and sign in with your IBM i User ID and Password.
StartNext to the "Start a new session" heading, choose "Dedicated" (the default) or "Shared", then press "Start". Use the radio buttons below to choose Quick connect (the default) or Preset (choosing a code page, screen, or preset again selects the corresponding radio button). While the session is starting, the elapsed seconds are shown (it takes a few seconds). "Open" in the list shows the 5250 screen in another browser tab.

The default host code page is 5026 Japanese Katakana (equivalent to 930 in IBM i Access Client Solutions) when the primary language of the IBM i is Japanese (2962 or 2930), and 037 otherwise. The default screen is 24x80. The connection is always to that IBM i partition.

The Preset list and the AUTOTYP script list are shown collapsed. Press a heading to expand it.
Open the screen inIn the settings window (the gear at the right end of the "Active sessions" heading), chooses where "Open" in the list opens the 5250 screen: "New tab" (the default) or "New window" (a small window with no address bar or tabs). The chosen value is saved in that browser.
Copy linkThe copy icon (Copy link) next to "Open" in the list copies the address of the 5250 screen to the clipboard. If you give it to another person, they can open the same session in their browser (for a dedicated session, only the first tab that opened it can use it).

"Help" at the top right of the admin screen and the help button (a circled i) on the 5250 screen toolbar open this guide.

Operation in the browser

  • The address of a 5250 screen is http://<IBM i>:<port>/. The port is shown in the list on the admin screen.
  • Closing the tab or the browser does not end the session (it stays signed on). Open it again with "Open" in the list to continue where you left off. Reloading works the same way.
  • To end a session, sign off on the 5250 screen, then in the list on the admin screen choose "Wait" and press "Disconnect". "Wait" waits until the session returns to the sign-on screen, and switches to "Immediate" when the specified number of seconds is exceeded. "Immediate" signs off with SysReq → 90 and then disconnects. If the sign-off does not finish within 15 seconds (for example, in the middle of a long process such as save or restore), the connection is simply dropped and the session ends. In this case the IBM i job may keep running until a break in its processing (the same as when you close a 5250 screen window in IBM i Access Client Solutions). If necessary, check with WRKACTJOB or similar.
  • The person icon on the 5250 screen toolbar shows whether the session is dedicated (one person) or shared (two people). Pressing it does not switch the mode. Whether a session is shared or dedicated is decided when the session is started.
  • The window mode switch and microphone (voice input) buttons that IBM 5250 MCP has are not shown in Open 5250.
  • Display settings — The toolbar toggles (input field highlighting, column separators, shift character display, blinking, crosshair ruler, cursor, hide toolbar, display language) are saved in the browser you use (a cookie). Whatever the port number, the same browser starts with the same settings; another PC starts with the defaults. The font is saved to the preset for a session started with a preset (quick connect starts with the defaults every time).
  • Where presets are saved — One file per preset, at presets/<preset name>.i5250 in the installation directory (for example /i5250/presets/LOCAL.i5250). Each line has the form "key=value". You can create, edit, and delete presets in the "Preset list" on the admin screen.
  • For operation of the 5250 screen itself (keys, toolbar, AUTOTYP, and so on), see the included IBM 5250 MCP User Guide (IBM5250-MCP-User-Guide-EN.pdf). Behavior and restrictions that differ from IBM 5250 MCP are listed in section 4.7 of the Open 5250 manual.
  • User-defined characters — IBM i sends only the values of user-defined characters, not their glyphs. When you get the glyphs with "IBM i user-defined character management" in the Settings window (the gear) of the admin screen, user-defined characters on the 5250 screen are drawn with those glyphs.
    • Pressing "Get" opens a window that asks for a User ID and Password. It connects to the FTP server of this partition, exports the user-defined characters of QIGC3232 (32×32) and QIGC2424 (24×24) with CPYIGCTBL, and retrieves them (the export goes to QTEMP of the FTP job, so no objects are left on IBM i; the password is not saved). The FTP server must be running (STRTCPSVR *FTP).
    • Required authority: *USE on the font tables (QIGC3232, QIGC2424) (IBM i Security, "Double-byte character set commands"). Operation has been verified with a *SECOFR class user.
    • 32×32 glyphs take priority; characters without one are drawn with the 24×24 glyph. User-defined characters with no glyph (not retrieved or not defined) are drawn as a dotted box with a diagonal-line glyph.
    • Pressing "Show" shows a list of the user-defined characters in another tab (the EBCDIC, PC (Shift-JIS), and Unicode codes, and the 24×24 and 32×32 glyphs).
    • After adding or changing user-defined characters, press "Get" again. The copied user-defined characters become characters in the Unicode Private Use Area (in order, starting with X'6941' = U+E000).
  • URL hotspots — URLs shown on the screen (http / https / www / mailto / ftp / file / gopher) are underlined, and the mouse pointer becomes a finger. Clicking one opens it in a new window (the same as the IBM i Access Client Solutions default "Underline URLs"). URLs inside input fields are not included.
    • Because browsers cannot open file:// URLs (for example FILE://GURI/IMG/658.JPG) directly, Open 5250 reads the file from the IFS of that IBM i and returns it. Only files whose URLs are shown on that session's current screen are returned. Files are read with the authority of the user running Open 5250 (the admin screen job) (the NetServer share authority check is not applied). Beforehand, confirm that users can access the folder, for example by opening it in Explorer.
    • PC commands (STRPCCMD) — Commands with which an IBM i program uses STRPCCMD to have the PC open a file (START + a shared-folder file such as START \\GURI\TMP\…\x.PDF, a file://, or an http://) are opened in a new window of the 5250 screen's browser. Only things a browser can display, such as PDF, text, and images, are supported. If the browser blocks the new window, nothing opens. Allow pop-ups for this site in the browser settings.
      • No command is run, either on IBM i or on the PC. Commands that run programs, such as starting Excel, cannot be used.
      • Only the "target" of a START ["title"] [/options] target that IBM i sent to that session with STRPCCMD can be opened. Everything remaining after removing the title and options is treated as one target: if it begins with http://, https://, or www., it is treated as a URL; if it begins with \\host\, //host/, or file://, it is treated as a shared-folder file. Anything else is not opened (for examples and details, see section 4.5.1 of the Open 5250 manual). The "Restrictions" below apply equally to the file location (the share name must be in the NetServer share definitions, and the file must be on that partition).
      • Text that cannot be read as UTF-8 is displayed as Shift_JIS.
      • File names may contain Japanese (DBCS). If a file name in lowercase English letters arrives as half-width Katakana (and also appears as half-width Katakana on the 5250 screen), switch to lowercase English with the character switch on the toolbar (A / ｱ, Ctrl+F3) before opening it. The PC command string is read according to the character switch setting at that time.
    • Restrictions: The share name in file://host/share-name/path is converted to an IFS path using the NetServer file share definitions (QSYS2.SERVER_SHARE_INFO) (for example, if share LMS points to /tmp/PCDOC, FILE://GURI/LMS/x.PPT becomes /tmp/PCDOC/x.PPT). Share names not in the definitions cannot be opened. Also, files can be opened only when the host name is that IBM i partition (system name, host name, or IP address); files on other servers cannot be opened (Open 5250 does not read other servers as a CIFS client). A host name that does not match by name is resolved to an IP address with IBM i name resolution (host table, DNS), and the file is opened if it is an IP address of this partition (because name resolution can take time, it starts as soon as a file:// appears on the screen, and the result is remembered for 10 minutes).

Multiple sessions

  • Each session uses its own port (in order starting at 5251) and runs as a separate interactive job on IBM i. Sessions in different processes do not affect each other (for sessions in the same process, see the next item).
  • The number of sessions that can run at the same time is set by "Maximum sessions" on the admin screen (default 10 = ports 5251 to 5260).
  • The number of sessions handled by one server process (node) is set by "Sessions per process" on the admin screen (1 / 10 / unlimited, default 10). A new session goes into the process handling the fewest sessions, and a new process is started only when no process can take it. Sharing a process makes starting faster and uses less memory, but if that process ends abnormally or is forcibly ended, all sessions in the same process end. Ending one session or a disconnect from IBM i ends only that session.
  • "Device name" in the list is the display device that IBM i assigned to the session (for example QPADEV0003). It is also the name of the interactive job.
  • When "Inactivity timeout" (5 to 300 minutes; blank = none) is set on the admin screen, a signed-on session that has no exchange with IBM i (sending an action key and so on, or a screen update) for that many minutes is ended with the same procedure as "Immediate". Sessions still at the sign-on screen are not affected. While a command or program is running (while the keyboard is locked, including long processes such as save that run without showing a screen), the session is not considered inactive, and counting restarts from the point when the run ends and input becomes possible. Whether the time has expired is checked every 15 seconds, so the session ends up to about 15 seconds after the specified time.
    • An open 5250 screen first shows the sign-on screen, then right away (1 to 2 seconds later) the screen goes blank and COMM659 (communication disconnected) appears on the bottom line. The session has ended, so that screen can no longer be used. To continue, start a new session from the admin screen.
    • It disappears from the list on the admin screen in about 5 seconds.
    • The range of values is the same as the IBM i system value QINACTITV, but the action is different. QINACTITV ends the job (when QINACTMSGQ is *ENDJOB) or disconnects it (when *DSCJOB). Open 5250 signs off, drops the connection, and ends the session itself. When both are set, whichever expires first takes effect.

Shared and dedicated

ModeBehavior
SharedA special use in which several people display and operate the same session at the same time (normal 5250 sessions use dedicated). When the same session is opened in several browsers or tabs, everyone can both see and type. One person's input also appears on the others' screens (the delay before it appears is the round-trip time of communication between the PC and IBM i, plus the 0.05 seconds the server takes to batch input, plus screen processing time. In an example measured over a VPN connection with a round trip of about 0.025 seconds, it was about 0.15 seconds. It varies with line conditions. If you type fast, several characters appear together). When someone presses an action key or similar, everyone's screen moves to the next screen. When people type into the same field at the same time, only the value of the person processed last remains (the characters of two people are never mixed).
DedicatedOnly the first tab that opened the 5250 screen can display it and type. When it is opened in another tab (another tab of the same browser, a tab of another browser on the same PC, a tab of a browser on another client (another PC), or a tab made with "Duplicate tab"; the owner is the tab, not the browser or the person), the message "This session is dedicated and is in use by another user." is shown and that tab is closed. After the "Dedicated release time" (admin screen settings, default 5 minutes; 0 = about 5 seconds) once the tab in use is closed, the session can be opened in another tab. Reloading the tab in use lets that tab keep using the session. If the PC in use goes down or the line stays disconnected, the "Dedicated release time" is counted from about 1 minute after it stops responding.
Caution
  • The 5250 screen ports have no authentication. Anyone who knows the port number can display and operate a shared session.
  • Even for a dedicated session, if you close the tab while still signed on, after the "Dedicated release time" (default 5 minutes) the next person who opens it can use that signed-on screen. Sign off when you leave your desk or finish using it.
  • If the tab using a dedicated session does not respond to the server for about 1 minute (the PC stops, the line is cut, the browser puts a background tab to sleep, and so on), that tab is no longer considered in use, and the session can be opened in another tab. When you return to that tab, you can keep using it if no other tab is using the session.
  • In dedicated mode, the only other tabs that can be closed automatically are tabs opened with "Open" on the admin screen and tabs made from them with "Duplicate tab". Tabs opened by entering the URL in the address bar (and their duplicates), for example, cannot be closed because of browser restrictions and remain as a blank screen (input is not possible). Close them by hand.
  • A session started from the admin screen does not reconnect automatically when the connection to IBM i is lost. When the host closes the connection, the session ends.

3 Using it from RPG and CL (ILE API)

With the commands (I5250xxx) from CL programs, and with the procedures of service program I5250/I5250API from ILE RPG, you can start a 5250 session, send keys and characters, and read the screen. Sessions are specified by port number.

Read this first
  • The admin screen must be running (it accepts the requests to start and end sessions). Only requests from the same partition (127.0.0.1) are accepted, and there is no authentication.
  • Right after a key is sent, the screen may still be the previous one. To read the next screen, save the screen before sending the key, then get the screen again every second until it changes (WAIT2 in the sample below). If you use only "input ready" as the condition, you will read the previous screen.
  • Right after sign-on, a screen such as "Display Program Messages" may come in between. Check with I5250FLD whether the cursor position is an input field, and if it is not, proceed with ENTER.
  • Rows (ROW) and columns (COL) are counted from 1. 0 means "the current cursor position". Specify the position of the data (the column after the attribute byte).
  • Characters are passed in the job CCSID (the API does the conversion). When the job CCSID is 65535, the default CCSID (DFTCCSID) is used.
  • Several programs can use the same session, but the API has no locking. Dedicated (*DEDICATED) only refuses other browser tabs; it does not refuse operations from the API. When programs may use a session at the same time, the callers must keep the order (for example, use it only after holding a data area in your own library with ALCOBJ).
  • Character literals passed from the command line with CALL ... PARM('...') are passed reliably only up to 32 bytes (IBM i specification). Pass longer values from variables in a CL program.

3.1 CL commands

On failure, the commands send escape message CPF9897 (receive it with MONMSG MSGID(CPF9897) and get the reason with RCVMSG MSGTYPE(*EXCP) MSGDTA(&MSG)). To check the description of each parameter, press F1 at the prompt (F4) to see the help.

SyntaxDescription
I5250STR PRESET(preset-name) MODE(*DEDICATED|*SHARED) PORT(&PORT)Starts a session and returns the port number in &PORT (*DEC 5 0). The default for MODE is *DEDICATED (dedicated). Can be used only within a CL program (because it returns a value).
I5250END PORT(n) OPTION(*CNTRLD|*IMMED) DELAY(*DFT|seconds)Ends a session. *CNTRLD (the default) waits DELAY seconds (0 to 99999; *DFT = the admin screen default of 300 seconds) for the session to return to the sign-on screen, and signs off with SysReq → 90 if it does not. *IMMED signs off with SysReq → 90 immediately. If the session is at the sign-on screen, either option ends it immediately.
I5250KEY PORT(n) KEY(key) ROW(row) COL(column)Sends a key. When ROW and COL (default 0 = the current position) are specified, the cursor is moved there before the key is sent. The key names are listed in the table below.
I5250TXT PORT(n) TEXT(characters) ROW(row) COL(column) KEY(ENTER|*NONE|key)Types characters and then sends a key (the default for KEY is ENTER; with *NONE, it only types). TEXT is up to 1024 bytes and can be an expression. Passing a CL variable as is also types its trailing blanks, so write it like TEXT(%TRIMR(&USER)).
I5250PST PORT(n) TEXT(characters) ROW(row) COL(column)Pastes several lines as a rectangle with the specified position as the top left corner (line break = X'25', up to 3000 bytes; no key is sent). TEXT can be an expression.
I5250SCR PORT(n) SCREEN(&SCR) ROWS(&R) COLS(&C) CSRROW(&CR) CSRCOL(&CC) READY(&RDY)Gets the screen. SCREEN (*CHAR 3564) is the rows joined in order; row n is the COLS columns starting at (n-1)*COLS+1. ROWS, COLS, CSRROW, and CSRCOL are *DEC 3 0, and READY (*CHAR 1) is '1' if input is ready. Can be used only within a CL program.
I5250FLD PORT(n) ROW(row) COL(column) LEN(length) TEXT(&T)Gets the characters at the specified position (TEXT is *CHAR 3564). LEN(0) (the default) means from that position to the end of the field; if the position is not an input field, CPF9897 is sent. Can be used only within a CL program.
I5250ATP PORT(n) SRCFILE(library/file) SRCMBR(member)
or I5250ATP PORT(n) STMF('path')		Reads an AUTOTYP script from a source member (the default for SRCFILE is *LIBL/QAUTOTYP) or a stream file and runs it. While reading, a temporary file is created at /tmp/I5250ATP-<job number>.TXT and deleted when finished.

3.2 RPG procedures (service program I5250/I5250API)

Declare them with /COPY I5250/QRPGLESRC,I5250API_H and bind with H BNDDIR('I5250/I5250'). Every procedure returns a return code (10I 0, 0 = normal); when it is not 0, get the reason with I5250_Error().

ProcedureDescription
I5250_Start(Preset : Mode : Port)Starts a session. Preset = preset name (32A VARYING), Mode = '*SHARED' / '*DEDICATED'; the started port is returned in Port (10I 0).
I5250_End(Port : Option : Delay)Ends a session. Option = '*CNTRLD' / '*IMMED', Delay = wait time (seconds; -1 = the admin screen default).
I5250_SendKey(Port : Key : Row : Col)Sends a key. Row and Col = 0 means the current position.
I5250_SendText(Port : Text : Row : Col : Key)Types characters (32000A VARYING) and then sends a key. With Key = '*NONE', it only types.
I5250_PasteText(Port : Text : Row : Col)Pastes several lines as a rectangle (line break = X'25'; no key is sent).
I5250_GetScreen(Port : Screen : Rows : Cols : CsrRow : CsrCol : Ready)Gets the screen. Screen is 3564A; row n is the Cols columns starting at (n-1)*Cols+1. Ready = 1 means input is ready.
I5250_GetFieldText(Port : Row : Col : Length : Text)Returns Length columns of characters from the specified position in Text (3564A VARYING). Length = 0 means to the end of the field.
I5250_RunAutotyp(Port : Script)Runs the body of an AUTOTYP script (65000A VARYING, line break = X'25').
I5250_RunAutotypStmf(Port : Path : Trim)Runs a script in a stream file (CCSID 1208). With Trim = '1', trailing blanks on each line are removed.
I5250_Error()Returns the error message of the previous call (512A VARYING).

Write the source in fixed form (H, D, and P specifications in fixed form, calculations in free form). Because EXTPROC(*DCLCASE) cannot be used in fixed-form D specifications, the declarations (I5250API_H) specify procedure names as character literals, like EXTPROC('I5250_Start').

3.3 Samples

The following two samples are included in library I5250 as programs and source (QCLSRC, QRPGLESRC).

ProgramDescription
SMPSGN (ILE CL)Uses the commands to sign on, read the first screen, SIGNOFF, and end the session. CALL I5250/SMPSGN PARM('LOCAL' 'user' 'password')
SMPSCR (ILE RPG)Uses the procedures to start a session, write the screen to the job log, get the characters of the input field at the cursor position, and then end the session. CALL I5250/SMPSCR PARM('LOCAL')

CL example (the essentials of SMPSGN: start a session, wait for the sign-on screen, sign on, and read the next screen)

             PGM        PARM(&PRESET &USER &PWD)
             DCL        VAR(&PRESET) TYPE(*CHAR) LEN(32)
             DCL        VAR(&USER) TYPE(*CHAR) LEN(10)
             DCL        VAR(&PWD) TYPE(*CHAR) LEN(32)
             DCL        VAR(&PORT) TYPE(*DEC) LEN(5 0) VALUE(0)
             DCL        VAR(&SCREEN) TYPE(*CHAR) LEN(3564)
             DCL        VAR(&BEFORE) TYPE(*CHAR) LEN(3564)
             DCL        VAR(&ROWS) TYPE(*DEC) LEN(3 0)
             DCL        VAR(&COLS) TYPE(*DEC) LEN(3 0)
             DCL        VAR(&CROW) TYPE(*DEC) LEN(3 0)
             DCL        VAR(&CCOL) TYPE(*DEC) LEN(3 0)
             DCL        VAR(&PROW) TYPE(*DEC) LEN(3 0)
             DCL        VAR(&READY) TYPE(*CHAR) LEN(1)
             DCL        VAR(&TRIES) TYPE(*INT) LEN(4)
             DCL        VAR(&LINE) TYPE(*CHAR) LEN(132)
             DCL        VAR(&MSG) TYPE(*CHAR) LEN(512)
             MONMSG     MSGID(CPF9897) EXEC(GOTO CMDLBL(ERROR))

/* Start the session (the port is returned in &PORT) */
             I5250/I5250STR PRESET(&PRESET) MODE(*DEDICATED) +
                          PORT(&PORT)
/* Wait for the sign-on screen (every 1 second, up to 30 seconds) */
             CHGVAR     VAR(&TRIES) VALUE(0)
WAIT1:       I5250/I5250SCR PORT(&PORT) SCREEN(&SCREEN) +
                          ROWS(&ROWS) COLS(&COLS) CSRROW(&CROW) +
                          CSRCOL(&CCOL) READY(&READY)
             IF         COND((&READY *NE '1' *OR +
                          &SCREEN *EQ ' ') *AND &TRIES *LT 30) +
                          THEN(DO)
             CHGVAR     VAR(&TRIES) VALUE(&TRIES + 1)
             DLYJOB     DLY(1)
             GOTO       CMDLBL(WAIT1)
             ENDDO
/* Type the user (at the cursor) and password (one row down), */
/* save the screen just before ENTER in &BEFORE, then ENTER  */
             I5250/I5250TXT PORT(&PORT) TEXT(%TRIMR(&USER)) +
                          ROW(&CROW) COL(&CCOL) KEY(*NONE)
             CHGVAR     VAR(&PROW) VALUE(&CROW + 1)
             I5250/I5250TXT PORT(&PORT) TEXT(%TRIMR(&PWD)) +
                          ROW(&PROW) COL(&CCOL) KEY(*NONE)
             I5250/I5250SCR PORT(&PORT) SCREEN(&BEFORE) +
                          ROWS(&ROWS) COLS(&COLS) CSRROW(&CROW) +
                          CSRCOL(&CCOL) READY(&READY)
             I5250/I5250KEY PORT(&PORT) KEY(ENTER)
/* Wait until the screen changes, then send row 1 as a message */
             CHGVAR     VAR(&TRIES) VALUE(0)
WAIT2:       I5250/I5250SCR PORT(&PORT) SCREEN(&SCREEN) +
                          ROWS(&ROWS) COLS(&COLS) CSRROW(&CROW) +
                          CSRCOL(&CCOL) READY(&READY)
             IF         COND((&READY *NE '1' *OR +
                          &SCREEN *EQ &BEFORE) *AND &TRIES *LT 30) +
                          THEN(DO)
             CHGVAR     VAR(&TRIES) VALUE(&TRIES + 1)
             DLYJOB     DLY(1)
             GOTO       CMDLBL(WAIT2)
             ENDDO
             CHGVAR     VAR(&LINE) VALUE(%SST(&SCREEN 1 &COLS))
             SNDPGMMSG  MSGID(CPF9897) MSGF(QCPFMSG) +
                          MSGDTA('1行目:' *CAT %TRIM(&LINE)) +
                          MSGTYPE(*INFO)
/* Type SIGNOFF, wait up to 30 seconds for the sign-on screen, end */
             I5250/I5250TXT PORT(&PORT) TEXT('SIGNOFF') KEY(ENTER)
             I5250/I5250END PORT(&PORT) OPTION(*CNTRLD) DELAY(30)
             RETURN

/* Failure: receive the reason, end the session immediately, return */
ERROR:       RCVMSG     MSGTYPE(*EXCP) MSGDTA(&MSG)
             IF         COND(&PORT *GT 0) THEN(DO)
             I5250/I5250END PORT(&PORT) OPTION(*IMMED) DELAY(0)
             MONMSG     MSGID(CPF0000)
             ENDDO
             SNDPGMMSG  MSGID(CPF9897) MSGF(QCPFMSG) MSGDTA(&MSG) +
                          MSGTYPE(*ESCAPE)
             ENDPGM

The handling for when a screen such as "Display Program Messages" comes in right after sign-on (checking with I5250FLD whether the position is an input field and proceeding with ENTER) is in the SMPSGN source.

RPG example (the essentials of SMPSCR: start a session, wait for the screen to arrive, and write the non-blank rows to the job log)

     HDFTACTGRP(*NO) ACTGRP(*NEW) BNDDIR('I5250/I5250')
     HCCSID(*CHAR:*JOBRUN)
      /COPY I5250/QRPGLESRC,I5250API_H
     DSMPSCR           PI
     D Preset                        32A
     DSleep            PR            10U 0 EXTPROC('sleep')
     D Seconds                       10U 0 VALUE
     DPort             S             10I 0 INZ(0)
     DScreen           S           3564A
     DRows             S             10I 0
     DCols             S             10I 0
     DCsrRow           S             10I 0
     DCsrCol           S             10I 0
     DReady            S             10I 0
     DTries            S             10I 0
     DIdx              S             10I 0
     DRowText          S            132A   VARYING
      * Start the session
       if I5250_Start(%trim(Preset) : '*DEDICATED' : Port) <> 0;
         Fail('開始できません: ' +I5250_Error());
       endif;
      * Wait until input is ready and the screen arrives (up to 30 seconds)
       for Tries = 1 to 30;
         if I5250_GetScreen(Port : Screen : Rows : Cols
               : CsrRow : CsrCol : Ready) <> 0;
           Fail('画面を取り出せません: ' +I5250_Error());
         endif;
         if Ready = 1 and Screen <> *BLANKS;
           leave;
         endif;
         Sleep(1);
       endfor;
      * Row n is the Cols columns of Screen starting at (n-1)*Cols+1
       for Idx = 1 to Rows;
         RowText = %trimr(%subst(Screen : (Idx - 1) * Cols + 1
             : Cols));
         if RowText <> '';
           SendMsg(%char(Idx) + ': ' + RowText : '*INFO');
         endif;
       endfor;
      * End (ends without waiting if at the sign-on screen)
       if I5250_End(Port : '*CNTRLD' : -1) <> 0;
         Fail('終了できません: ' +I5250_Error());
       endif;
       *INLR = *ON;
       return;

Fail (ends the session immediately and then sends an escape message) is at the end of the SMPSCR source, and SendMsg is in I5250/QRPGLESRC,I5250MSG, which SMPSCR includes.
